# electron/ — desktop shell (standalone app)

Electron main process that runs the game without a browser. It serves the Vite build (`dist/`) from its own local http
server, opens one `BrowserWindow` on it, and pipes that origin's `/ws` to a relay. **The build carries no server**
(2026-09-15, user decision): a relay runs only from the repo via `start-server.bat`; with no address configured the shell
pipes to this PC's `ws://127.0.0.1:8787/ws`. It changes nothing in `src/`: the renderer sees the same same-origin `/ws` it
sees behind the Vite proxy. Loading over http instead of `file://` is what keeps `src/` untouched (`location.host` must exist).

## Files

| File | Responsibility |
|---|---|
| `main.ts` | Lifecycle: option parsing → relay target (`resolveRelay`) → window http server (`APP_PORT`, `listenStable`) → window. Single-instance lock, no menu, F11 fullscreen, Escape hook, window state, permission handler (`pointerLock`, `fullscreen`), external links to the browser, `session.flushStorageData()` every `SAVE_FLUSH_MS` and on `before-quit`, `/__scav/relay` route |
| `static.ts` | `attachStatic(server, root)` — serves `dist/` first, falls through to the window server's own handler (`/__scav/relay`, 404); blocks `..`, `no-cache` |
| `wsProxy.ts` | `attachWsProxy(server, url)` — raw socket pipe of `/ws` upgrades (query `?t=&n=` intact) to one fixed relay `URL`; an unreachable relay just drops the page socket |
| `windowState.ts` | `<userData>/window-state.json` — size, position, maximized, fullscreen; drops a position on a vanished monitor |
| `build.mjs` | rolldown bundle of `main.ts` (+ `src/shared/net.ts`) → `dist-electron/main.js` (`electron` external, no `server/`, no `ws`); bakes `default-relay.txt` into `__SCAV_DEFAULT_RELAY__` via `transform.define` |
| `default-relay.txt` | Build-time default relay address (one line); `scripts/pack-release.mjs` also writes it as the deploy folder's `server.txt` |
| `launcher.cs` | Stub launcher source: starts `app\SCAVANGER.exe` with the same arguments and the deploy folder as cwd; compiled by `scripts/pack-release.mjs` with `csc.exe` (`/target:winexe`, `/win32icon`) |
| `resources/icon.ico` | App icon generated by `npm run icon` (`scripts/make-icon.mjs`); used by electron-builder and the stub |

## Window port = save origin

localStorage (every character slot, stash, `scav.sessionToken`) is keyed by origin `http://127.0.0.1:<window port>`, and
the relay keys server profiles by that token. So the window port is **fixed**: `APP_PORT` 8790, then `8790 → 8799` in
order, never OS-chosen, never shared with the relay port. If all ten are blocked, startup fails with a dialog. Changing
`--app-port` starts a fresh save. `isPortBlocked` treats `EADDRINUSE` and `EACCES` alike.

**Windows reserved ports**: WinNAT (Hyper-V / WSL / Docker) reserves random 100-port ranges at boot; `listen` then fails
with `EACCES` even as admin (`netsh int ipv4 show excludedportrange protocol=tcp`). When all window ports are reserved,
`startupFailureMessage` shows the fix (the window range only — the shell opens no relay port):

```
net stop winnat
netsh int ipv4 add excludedportrange protocol=tcp startport=8790 numberofports=10
net start winnat
```

## Relay address resolution

In-game `설정 › 서버 설정` (renderer localStorage `RELAY_STORAGE_KEY`) beats everything: the renderer then connects to that
address directly and ignores same-origin `/ws`. Otherwise the shell picks the `/ws` target, first hit wins (`resolveRelay`):

| # | Source | `/__scav/relay` `source` |
|---|---|---|
| — | `--local` / `SCAV_LOCAL=1` → skip all of the below, this PC's server | `--local · 이 PC 의 서버` |
| 1 | `--relay=<address>` | `--relay` |
| 2 | `SCAV_RELAY` | `SCAV_RELAY` |
| 3 | `server.txt` (legacy name `relay.txt`) — first non-empty, non-`#` line, BOM stripped; searched in `PORTABLE_EXECUTABLE_DIR` → `execPath` dir → its parent (the deploy root above `app/`) → `cwd` | `server.txt` |
| 4 | Baked `__SCAV_DEFAULT_RELAY__` (`default-relay.txt`, or `SCAV_DEFAULT_RELAY=… npm run app:dist`) | `build default` |
| 5 | Nothing → `ws://127.0.0.1:${NET_DEFAULT_PORT}/ws` (this PC's `start-server.bat`) | `이 PC 의 서버 · start-server.bat` |

Addresses are normalized by `src/shared/net.ts` `relayUrlFrom` (same function as the settings UI and renderer); a value that
is not an address fails startup with a dialog naming it and where it came from. `GET /__scav/relay` (`NET_SHELL_RELAY_ROUTE`)
returns `{target, source, embedded}`; `embedded` is a contract field and is **always `false`** now. When the target is down the
proxied socket closes at once and the renderer goes offline and probes in the background like any other target.

## Flags (flag or env, flag wins)

| Flag | Env | Meaning |
|---|---|---|
| `--app-port=<n>` | `SCAV_APP_PORT` | Window port (default 8790) — changes the save origin |
| `--relay=<url>` | `SCAV_RELAY` | Proxy `/ws` to that relay |
| `--local` | `SCAV_LOCAL=1` | Ignore configured addresses, use this PC's server (`ws://127.0.0.1:8787/ws`) |
| `--devtools` | `SCAV_DEVTOOLS=1` | Enable DevTools |
| `--raw-escape` | `SCAV_RAW_ESCAPE=1` | Disable the Escape hook (diagnostics) |
| `--user-data=<dir>` | `SCAV_USER_DATA` | Test isolation: `app.setPath('userData')` before the lock and ready |
| `--hidden` | `SCAV_HIDDEN=1` | Test: never show the window (rAF drops to a few per second) |

`--port`, `--lan` and `--lazy-relay` were removed with the embedded relay (2026-09-15).

## Escape

The shell never touches the key (no `preventDefault`, no synthetic forward — forwarding delivered Escape twice). On every
Escape **key-up**, `handleEscape` (`before-input-event`) runs `executeJavaScript(SHELL_RELOCK, true)`, calling the page's
`window.__scavShellRelock` (`src/game/ResumeGate.ts`), which re-locks only when no one owns the cursor. The real timing fix
lives in `src/shared/Input.ts` (re-lock deferred after Escape / user exit); the hook is a harmless extra nudge through the
same gate. In the shell the resume gate never shows, and the cursor is hidden (`body.desktop-nocursor`) whenever no
cursor owner exists. Known automation limits (`scripts/smoke-desktop.mjs`): CDP-injected keys bypass
`before-input-event` (the smoke injects Escape with `webContents.sendInputEvent`), and a hidden window cannot take
pointer lock, so lock timing stays a manual check.

## Deploy folder

`npm run app:dist` = icon → `app:build` → `electron-builder --win dir` → `scripts/pack-release.mjs`:

```
release/SCAVANGER/
  app/                    electron-builder dir output (SCAVANGER.exe, .pak, dll, locales …)
  SCAVANGER.exe           stub launcher (launcher.cs)
  server.txt              relay address — the only file a player edits
```

Exactly three entries — no server. Whoever hosts runs `start-server.bat` from the repo (see `server/README.md`).

## Rules

- The shell must never start a relay or import `server/` — builds ship no server (`smoke-desktop` checks the bundle, the
  asar and the ports the app listens on).
- Keep `package.json` `build.electronDist = "node_modules/electron/dist"`: without it electron-builder downloads and
  renames `win-unpacked.tmp`, which endpoint security scanners lock, failing `app:dist` with `EPERM … rename`.
- Never serve the window from an OS-chosen port, and never move it to dodge a reserved range — the port is the save.
- The renderer loads from `127.0.0.1`, so `isDevHost()` is true and the dev console exists in the packaged app.
- Shell checks: `node scripts/smoke-desktop.mjs` (`--release` also checks the deploy folder).
