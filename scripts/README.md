# scripts/

Node scripts for running and verifying the game. None of them are part of the build.

> **2026-09-08 — 튜토리얼 옵트아웃**: 튜토리얼(`src/tutorial`)은 **새 프로필**에서 자동으로 시작해 방 용도 ·
> 제작 · 터미널 · 탑승을 순서대로 잠근다. 스모크는 전부 새 프로필로 부팅하므로, `smoke-tutorial.mjs` 를
> 제외한 모든 스크립트는 `evaluateOnNewDocument` 안에서 `scav.tutorial` 을 `{done:true}` 로 심고 시작한다.
> 새 스크립트를 만들 때도 그 한 줄을 넣는다.

| `verify.mjs` | **Verification runner** — `npm run verify` (smokes mapped to the folders changed in the working tree) / `npm run verify:all` (everything, before a merge). Runs typecheck (client + server), `net:selftest` and optionally `vite build` in parallel, starts vite (5273) and the relay (8787) when they are not up, restarts the relay before `e2e-mp` (stale public lobbies hijack quick match), runs the smoke scripts in 4 staggered lanes (each owns a headless Chrome on the GPU), then `e2e-mp` alone. Prints one line per script + the `FAIL` lines, full output in `logs/<name>.log`, records `logs/last-run.json` for `--rerun-failed`, and ends with a `docs line:` to paste into `docs/VERIFICATION.md`. `--list` shows the folder → script map (`SMOKES` table at the top — register new smokes there). |

| `lan-address.mjs` | Prints the LAN IPv4 other machines should use to reach this one — `start-server.bat` puts it in the banner, and it is the value that goes into `electron/default-relay.txt`. `--all` lists every candidate with its adapter, `--url` prints the whole `ws://host:8787/ws` line. A dev box has several IPv4 addresses (Hyper-V / WSL / VPN switches) and `ipconfig` order ranks nothing, so virtual adapters are demoted by name and 192.168 > 172.16-31 > 10 wins. Imports `src/shared/net.ts` for the port and ws path, so it runs under type stripping (the bat passes `--experimental-strip-types` for Node 22). |

| `shots-pitch.mjs` | **Screenshot helper, not a smoke** (no assertions, no exit code, not registered in `verify.mjs`): fills the pitch wiki's image slots — `docs/pitch/assets/*.png`, which the [pitch wiki pages](../docs/pitch/README.md) (`docs/pitch/pages/NN-*.html`) pick up automatically. Covers the 함선 UI (인벤토리 · 캐릭터 · 임플란트 패널 · 기업 · 함선 탭 · 작업대 제작 · 서재 · 온실 · 시설 관리), the 함선 3D (복도 · 터미널 · 워프), all five planets, and the raid (교전 · 적 무리 · 정찰 / 배리어 임플란트 · 상단 시점 조준 · 궤도 폭격 · 탈출 카운트다운). `node scripts/shots-pitch.mjs [url] [name ...]` — extra args pick individual shots. Two things it must keep doing: PNGs are written to a **staging dir outside the repo** and copied in only after the browser closes (writing into the project while `npm run dev` is up makes Vite full-reload the page and throws `window.__game` away mid-run), and each shot is retried once for the same reason. Raids are started straight from `game:newMission` — never `hub.setPlanet`, whose warp cutscene leaves a camera override behind. |
| `pitch-webp.mjs` | **Deploy helper, not a smoke** (not registered in `verify.mjs`): writes a `<name>.webp` next to every `docs/pitch/assets/<name>.png`. The pitch wiki is published straight from the repo (GitHub Pages, no build), so the committed files are what a visitor downloads — 30 MB of PNG was the first paint. `npm run pitch:webp` (`--force` re-encodes, `--quality 0.9`, extra args pick individual names); it skips a PNG whose `.webp` is already newer, and refuses to write one that came out **larger** than the source. Encoding is done by the same local Chrome the shot scripts drive (`canvas.toDataURL('image/webp')`) — cwebp/ImageMagick/sharp are not installed here, and on Windows `convert` is the FAT→NTFS tool, not ImageMagick. The PNGs stay as the originals and as what `shots-pitch.mjs` writes; `docs/pitch/app.js` probes the `.webp` first and falls back to the `.png`, so **`data-src` in the 23 pages never changes**. Run it after `shots-pitch.mjs` adds or replaces a shot. |
| `logs/`, `shots/` | Runner output and screenshots (git-ignored). |

Every smoke script takes the vite URL as its first argument (default `http://localhost:5273/`), launches its own headless
Chrome on the **real GPU** (`GL_ARGS`: ANGLE D3D11, 10–50 s per script; `SMOKE_GL=swiftshader` = CPU rasterizer, ~10× slower),
stubs `requestPointerLock` (a real lock would trap the OS cursor in the hidden window — Windows ClipCursor) and fakes
`pointerLockElement`, waits on **simulation time** (`ctx.time`) and dispatches key taps as keydown+keyup in one frame on
`document.body`. `waitFor` defaults to 60 s so four scripts can share the machine. Checks build on each other, so the unit of
re-run is the whole script.

**여러 에이전트가 동시에 편집 중일 때는** vite 의 full-reload 가 스모크를 죽인다 — 전용 인스턴스
(`npx vite --port 5299`, HMR 없음)를 띄우고 그 URL 을 인자로 넘기거나, 편집이 멈춘 창에서 돌린다.
