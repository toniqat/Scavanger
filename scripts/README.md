# scripts/

Node scripts for running and verifying the game. None of them are part of the build.

> **2026-09-08 — 튜토리얼 옵트아웃**: 튜토리얼(`src/tutorial`)은 **새 프로필**에서 자동으로 시작해 방 용도 ·
> 제작 · 터미널 · 탑승을 순서대로 잠근다. 스모크는 전부 새 프로필로 부팅하므로, `smoke-tutorial.mjs` 를
> 제외한 모든 스크립트는 `evaluateOnNewDocument` 안에서 `scav.tutorial` 을 done 으로 심고 시작한다.
> 새 스크립트를 만들 때도 그 한 줄을 넣는다.
>
> **2026-09-14 — 저장이 v2(3트랙)다.** 심는 모양이 바뀌었다:
> `{ version: 2, tracks: { raid: { step: null, done: true }, ship: { step: null, done: true }, build: { step: null, done: true } } }`.

| `verify.mjs` | **Verification runner** — `npm run verify` (smokes mapped to the folders changed in the working tree) / `npm run verify:all` (everything, before a merge). Runs typecheck (client + server), `net:selftest`, `data-check` (`data/*.csv` 스키마) and optionally `vite build` in parallel, starts vite (5273) and the relay (8787) when they are not up — **unless every selected script is `standalone: true`** (`smoke-server-dist` · `smoke-pitch` use neither, and waiting for a vite they never touch cost ~20 s), restarts the relay before `e2e-mp` (stale public lobbies hijack quick match), runs the smoke scripts in 4 staggered lanes (each owns a headless Chrome on the GPU), then `e2e-mp` alone. Prints one line per script + the `FAIL` lines, full output in `logs/<name>.log`, records `logs/last-run.json` for `--rerun-failed`, and ends with a `docs line:` to paste into `docs/VERIFICATION.md`. `--list` shows the folder → script map (`SMOKES` table at the top — register new smokes there) plus the **`EXTRA_PATHS`** rows: `folders` only understands `src/<name>` and `server/`, so anything living outside them (`docs/pitch/` → `smoke-pitch`) is picked by path instead. |

Every smoke script takes the vite URL as its first argument (default `http://localhost:5273/`), launches its own headless
Chrome on the **real GPU** (`GL_ARGS`: ANGLE D3D11, 10–50 s per script; `SMOKE_GL=swiftshader` = CPU rasterizer, ~10× slower),
stubs `requestPointerLock` (a real lock would trap the OS cursor in the hidden window — Windows ClipCursor) and fakes
`pointerLockElement`, waits on **simulation time** (`ctx.time`) and dispatches key taps as keydown+keyup in one frame on
`document.body`. `waitFor` defaults to 60 s so four scripts can share the machine. Checks build on each other, so the unit of
re-run is the whole script.

**vite 를 여는 스모크는 `quietViteHmr(page)` 를 건다** (2026-09-11, C-65 — `quiet-hmr.mjs`). 여러 에이전트가 같은 트리를
편집하면 남의 저장 한 번이 vite full-reload 를 불러 스모크를 아무 시점에나 죽인다. 새 스크립트는 `page.goto` **전에**
한 줄(`import { quietViteHmr } from './quiet-hmr.mjs';` + `await quietViteHmr(page);`)을 넣고, **페이지를 여러 개 여는
스크립트는 페이지마다** 부른다. 싱글 플레이 스모크가 릴레이까지 막고 싶으면 `{ parkRelay: true }` 다 — 기본값은
릴레이를 건드리지 않는다. vite 를 안 여는 스모크(`smoke-server-dist` · `smoke-desktop` · `smoke-pitch`)는 필요 없다.
그래도 남는 흔들림(HMR 이 아닌 이유의 재빌드 등)이 있으면 전용 인스턴스(`npx vite --port 5299`, HMR 없음)를 띄우고
그 URL 을 인자로 넘긴다.

**`import('/src/…')` 로 들여온 모듈은 앱이 쓰는 그 모듈이 아닐 수 있다** (2026-09-14). vite dev 는 서버가 떠 있는 동안
파일이 한 번이라도 바뀌면 **자기가 고쳐 쓰는 import 에 무효화 도장을 찍는다**(`/src/shared/library.ts?t=1789354142878`).
그 도장은 서버의 모듈 그래프에 살아서 **전체 새로고침을 해도 그대로**이므로, 스모크가 손으로 적은 도장 없는 경로는
그대로 받아져 **모듈이 두 번 평가된다** — 상수 · 순수 함수를 읽기만 할 때는 값이 같아 티가 안 나지만, 그 사본의
상태를 **고치면**(맵에 줄을 넣거나 export 를 스텁하거나) 앱은 아무것도 못 본다. 실측(2026-09-14): 나흘 된 5273 에서
`ITEM_ALIASES.set(…)` 이 앱에 안 보였고(`sameMap:false`) 갓 띄운 vite 에서는 보였다 — 오래 산 서버에서만 빨개지는
전형적인 모양이다. 그래서 **모듈 상태를 건드리는 스모크는 이 문서가 실제로 받아 온 URL 로 import 한다**
(`smoke-library-consumers.mjs` 의 `window.__imp` — resource timing 에서 그 경로의 항목을 찾아 그 URL 을 import 하고,
없으면 맨 경로로 물러선다. `page.evaluateOnNewDocument` 에서 `performance.setResourceTimingBufferSize` 를 올려 둬야
앱이 받은 항목이 버퍼 밖으로 밀려나지 않는다). 읽기만 하는 스모크는 지금처럼 둬도 된다.
