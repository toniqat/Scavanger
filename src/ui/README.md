# src/ui — HUD & menus (`HudSystem`)

Arc Raiders-style minimalist HUD and all full-screen menus. Everything is plain DOM under `ctx.uiRoot`
(no React), styled by `styles/base.css`. Korean text throughout. Components only touch the DOM when a
value actually changes; moving elements use `transform`.

Import via `@/ui` → `HudSystem`, `OBJECTIVE_TEXT`.

| File | Purpose |
|---|---|
| `HudSystem.ts` | `GameSystem` (`name: 'hud'`). Builds two `.hud` layers (overlay: vignette/edge flash/damage arcs/scope; HUD: everything else), the deploy overlay, the tactical map and the five menus. Shows the HUD only in gameplay phases + `deploying`, hides it while `ctx.uiBlockers` has `'menu'` or the player is dead — **except in multiplayer**, where a dead local player keeps the HUD with `.spectating` on the HUD root (CSS hides reticle / vitals / weapon / prompt; squad list, nameplates, pings, notifications stay). Drives the default objective flow on `game:phaseChanged` / `extraction:boarded` / `extraction:tick` (emits `ui:objective`). Wires `MapScreen.setPingSource(() => pings.getPings())`. | `hud/Pings.ts` | Middle-mouse pings (`MouseButtons.PING`, 0.3 s cooldown, while gameplay active + pointer locked). ## Lobby state → UI mapping
| `ctx.phase` | `ctx.net` | `ctx.net.lobby` | lobby screen open (`ui:lobbyToggled`) | Shown |
|---|---|---|---|---|
| `menu` | null | — | — | `TitleMenu` (멀티플레이 → inline "사용 불가") |
| `menu` | set | null | false | `TitleMenu` |
| `menu` | set | null | true | `LobbyMenu` join view |
| `menu` | set | set | any | `LobbyMenu` room view (also right after a mission ends: `game:abort/over/complete` → phase `menu` with the lobby still set) |
| any other | — | — | — | neither; `net:gameStarting` hides the lobby immediately |

`net:lobbyLeft {left}` → whatever the open flag says (join view or title); `{hostLeft|disconnected|kicked}` → lobby screen forced open with the reason inline.

## Events emitted
`game:newMission {seed}`, `game:abort`, `game:paused {paused:false}`, `ui:objective`, `ui:lobbyToggled {open}`, `ui:notify` (lobby/title feedback),
`ping:placed {id, position, kind, expires}` (local and squad pings), `ping:removed {id}`, `ui:mapToggled {open}`,
`audio:play {id:'ui_click'|'ui_equip'}` (ping / map / scope sounds are played by AudioSystem from `ping:placed`, `ui:mapToggled`, `player:aimChanged`).
Net calls: `connect`, `setPlayerName`, `createLobby`, `joinLobby`, `leaveLobby`, `setReady`, `startGame`, `getInviteUrl`, `send({t:'ping'}, 'others')`.

## Pointer lock etiquette
Anything that opens a full-screen UI adds its `ctx.uiBlockers` token **first** and only then calls `ctx.input.exitPointerLock()`;
GameFlow pauses on any lock loss that happens with no blocker present. When a UI closes back into gameplay it requests the lock
again (map, inventory, pause resume) — deferred one microtask so a synchronous phase change right after the close wins. Chrome
may refuse a re-lock for ~1 s after an Esc-triggered exit; the click-to-lock fallback in `PlayerSystem` covers that.
`SpectateOverlay`, `Squad` and `Nameplates` never take a blocker token and are `pointer-events:none`.
