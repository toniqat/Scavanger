## 3. 계약 (리드가 먼저 커밋 — 에이전트는 읽기만)

### 3.1 `src/shared/types.ts`

- `ItemCategory` += `'meal'`(요리) · `'pouch'`(주머니) · `'key'`(열쇠)
- `MealBuff` — 요리가 올리는 **파생 수치** 한 가지. 전부 이미 `DerivedStats` 에 있는 필드 이름이다:
  `'carryCapacity' | 'maxStamina' | 'staminaRegenMul' | 'healPowerMul' | 'gritChance' | 'skillGainMul' |
   'gatherYieldMul' | 'searchSpeedMul' | 'detectRadius' | 'useSpeedMul' | 'interactSpeedMul' | 'durabilityLossMul'`
- `MealDef { buff: MealBuff; amount: number; tier: 1 | 2 }` → `ItemDef.meal?`
- `PouchDef { cols: number; rows: number; accepts: readonly ItemCategory[] }` → `ItemDef.pouch?`
- `StrainDef { outputDefId: string; outputQty: number; cultureHours: number }` → `ItemDef.strain?`
- `MediumDef { uses: number; speedMul: number }` → `ItemDef.medium?`
- `LoadoutSlot` += `'pouch'` (append-only; `WeaponSlot` 은 `Exclude<…, 'bag'|'armor'>` 이므로 **`'pouch'` 도 뺀다**)
- `InventoryRef` += `getPouchSize()` · `getEquippedPouch()`

> **왜 `MealBuff` 가 `DerivedStats` 의 필드 이름인가.** 버프를 새 개념으로 만들면 player · weapons · world ·
> inventory 가 전부 그 개념을 읽어야 한다. 파생 수치에 접어 넣으면 **소비자가 한 줄도 안 바뀐다** —
> 이미 `derived` 를 읽고 있기 때문이다. 크레딧 · 판매가 배수는 **일부러 뺐다**: 서버가 크레딧을
> 사유별로 검증하므로(E-4) 클라이언트 배수는 곧 `credits:tx` 거절이 된다.

### 3.2 `src/shared/progression.ts`

```ts
export interface PlayerProfile {
  /** 다음 레이드에 실릴 요리 def id. 고정 1칸이라 배열이 아니다. */
  meal?: string | null;
  /** 이번 레이드에 실려 있는 요리. */
  mealActive?: string | null;
}
export interface ProgressionRef {
  getMeal(): string | null;
  getActiveMeal(): string | null;
  /** 함선 전용. 요리 하나를 소비해 다음 레이드분에 싣는다. 이미 차려 둔 요리는 **교체**된다(사유 아님). */
  useMeal(defId: string): string | null;
  /** 공유 함선 식탁: 남이 차려 준 요리를 아이템 소모 없이 받는다. 호스트가 보낸 것만 받는다 (net 가 가드). */
  serveMeal(defId: string): void;
}
```

**`armPreps()` · `clearActivePreps()` 가 식사도 함께 옮기고 비운다** — `game/` 은 한 줄도 안 바뀐다.
계약 주석에 그렇게 적는다. 수명 규칙은 준비물과 동일(사망해도 그 레이드는 유지).

`mealActive` 는 `derived` 재계산의 입력이 된다 — `afterPrepsChanged` 와 같은 자리에서 `recomputeDerived()`.

### 4.5 `progression` (+ `net` 와이어)

- `PlayerProfile.meal` / `mealActive` 영속화. ⚠ **`Profile.migrate` 에 두 필드를 넣는 것이 결정적이다** —
  migrate 의 결과가 곧 다음 `saveProfile` 의 내용이라, 빠뜨리면 새로고침 한 번에 사라진다
  (2026-09-09 `accent` 사고, 2026-09-11 `prep` 과 같은 자리).
- `getMeal` · `getActiveMeal` · `useMeal` · `serveMeal`, `progress:mealChanged`.
- `armPreps()` · `clearActivePreps()` 가 식사도 함께 옮기고 비운다 (game/ 무변경).
- **`derived` 에 접기**: `recomputeDerived` 끝에서 `mealActive` 의 `MealDef` 를 해당 필드에 더한다.
  `*Mul` 은 배수에 가산(0.15 = +15 %), 나머지는 단위 그대로. `durabilityLossMul` 은 음수 amount 다.
  하한을 둔다 — 어떤 배수도 0 밑으로 내려가지 않는다.
- **net**: `meal serve {defId}` — 보내는 쪽은 공유 함선의 식탁에서만, 받는 쪽은 **로비 호스트가 보낸 것만**
  (「남에게 영향 주는 메시지는 권위에서만 받는다」 E-4). 호스트는 보낸 사람이 로비 멤버인지 · 같은 공유 함선인지
  검사하고 재방송한다. 받으면 `ctx.progression.serveMeal(defId)`.
- **`progression/README.md` · `net/README.md` 갱신.**

### 4.6 `ui` — 식사 배지 · 툴팁 · 제작 카드

- `hud/EnvBadge` 옆에 **식사 배지** (`progress:mealChanged` 의 소비자, 레이드에서만):
  요리 이름 + `MEAL_BUFF_LABEL_KO` 한 줄.
- `hud/ItemTip`: `def.meal` 이면 「다음 레이드 1회분 · <버프> +n」, `def.pouch` 면 「<가로>×<세로> · <받는 종류>」,
  `def.strain` 이면 「배양조 n시간 · 산출물」, `def.medium` 이면 「배양 n회 · 속도 +n %」.
- `hud/ShipManage` 의 `MODEL_GLYPH` 에 새 모델 4종 (지금 타입 에러).
- 출격 준비 점검에 「식사를 차리지 않았습니다」 한 줄 — **막지 않는다** (준비물 경고와 같은 결).
